# AI 安全运营业务配置

`ai-soc-configuration.json` 是使用通用业务配置协议的模板，不依赖专用 SOC 页面或聊天组件。它没有内置员工身份、凭据、告警数据或自动运行授权。

## 采用模板

先创建一个新的业务草案，将模板的 `scope`、所有定义的 `domain`、`sources[0].sourceId` 和对象类型的 `sourceId` 绑定到草案实际分配的值。通过原业务配置服务预览，检查对象、映射和指标后再采用。不要把示例范围直接当作已经登记的业务，也不要覆盖已有业务配置。

采用后提供总览、T1 告警研判、T2 深度调查、T3 威胁狩猎、响应与核验、检测改进六个看板，以及对应明细与原始工作。可在现有业务配置中继续调整指标和布局。配置采用不会自动创建员工、启动任务、读取外部系统或授予执行权限。

## 原始事实与员工结果

`ai-soc-work-item` 保存原始事实，类别区分五类工作。其余五个对象类型保存员工结构化结果，各自按原始对象 ID 去重，并通过 `original` 引用原始工作。更新同一对象的结果会产生新版本，统计只读取最新版本。

真实员工任务使用现有 `teloa_business_object_result_record` 工具。任务必须固定到原始工作，结果映射必须使用独立对象类型。`object_id`、`original`、`employee` 和 `source_task` 由宿主执行上下文提供；模型只填写 `result`。五个映射可按实际部署绑定岗位对应的 `roleId`，不在通用模板中固定某个安装实例的员工身份。

示例 T2 结果正文：

```json
{
  "title": "生产身份异常调查结论",
  "summary": "证据与影响范围摘要",
  "lifecycle": "待响应",
  "outcome": "确认入侵",
  "work_status": "已完成",
  "severity": "高",
  "created_at": "2026-10-11T00:00:00.000Z",
  "duration": 180,
  "evidence": "证据引用与可核实结论"
}
```

时间为原工作的开始时间，耗时单位为秒，缺失耗时可省略。结论需依据真实证据；示例不代表真实调查。

## 统计口径

- 员工处理状态与业务生命周期独立。员工完成分析不等于事件已经关闭。
- 响应获批、执行完成与效果核验独立。未核验响应仍计为未完成。
- 总数按对象去重；事件、告警、狩猎、响应与检测候选分别统计，不相加充当告警处理量。
- 平均耗时只统计员工已完成且有合法耗时的结果。缺失值显示未知并披露缺失字段，不当作零。
- 模板不计算准确率、成本节省或 ATT&CK 覆盖率。百分位耗时、SLA 和真实数据接入需另行配置、验证。
- 关联记录用于追溯，不授予额外访问权限，不把结构化结果当作原始事实或已批准动作。

## 验证

在仓库根运行：

```sh
node --test packages/contract/tests/ai-soc-configuration.test.ts
node --test packages/backend/tests/business-ai-soc-template.test.ts
```

后端用例需要本机容器引擎。它使用隔离 PostgreSQL，验证真实配置预览与采用、固定对象结果、幂等改版、原始事实保留、统计分母与六个看板；不调用模型或生产系统。
