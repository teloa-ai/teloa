# Teloa 工作台与业务

Teloa 的产品定位是通用 AI 工作台。安全是第一个业务 MVP，通用会话不需要选择安全业务才能开展工作。

公共部分包括会话、任务、持续计划、协作话题、资料引用、产物版本和审批机制。它们有各自的身份；同一个业务对象可以关联多个任务与会话，不从案件编号派生会话 ID。

业务模块提供专业对象、规则、工具与视图。安全业务可以使用案件和证据，设计业务可以使用设计稿和素材，不要求不同业务复用安全专用枚举。

业务面组织专业对象、责任、任务、规则和交付。数据面提供可查询的来源、事件、对象、证据、快照、版本和血缘。执行面接收有授权边界的外部动作，并分别返回受理与效果；批准、执行受理、执行效果是不同状态，批准不能直接显示为外部操作成功。Harness 提供会话、模型、记忆、Skill、工具、沙箱、调度和运行轨迹，公共任务、协作、审批、成果与审计贯穿三面。

数据面与执行面按行为区分，不按 MCP、插件或连接器区分。同一连接可以提供读取和写入工具，但读取范围和执行权限分别声明、授权和核验。实时告警、订单和工单状态属于数据面；稳定的制度、SOP 和系统说明属于工作资料；隔离、发送、发布和修改外部对象属于执行面。功能说明见 [Teloa 文档](https://docs.teloa.ai/)。

DSH 提供原生会话、模型、输入引用、工具运行和插件机制。Teloa 通过公开服务及插槽组合工作区，不复制原生编辑器。此资料描述设计边界，不表示其中所有功能已经实现。

数字同事对岗位结果负责。Skill 是经过验证、可重复使用的方法，不是 Agent 的能力白名单；没有合适 Skill 或既有方法未达到完成判据时，Harness 与模型仍可在当前沙箱和已有授权范围内自主规划、编写临时代码、组合工具并验证结果。

权限分为自主边界、外部访问身份和本次工作范围。缺少业务文档、SOP 或样本属于资料不足；目标明确但无法读取 Lark 文档或调用外部系统属于权限不足。文档链接只定位目标，不提供访问权。行业模板可以声明资料、连接和最低权限依赖，但不携带凭据，也不替用户完成授权。

知识正文统一规范为版本化 Markdown：粘贴文本直接生成，上传文档保留原件后解析，在线文档经授权读取后形成固定快照。Lark、Notion、Confluence 等由通用插件提供连接器，用户授权后形成连接实例，具体文档再作为知识来源。数据库保存来源、版本、范围与关系，检索索引可从 Markdown 重建；会话与任务引用具体版本，后续同步不改写历史依据。

资料按用途分为业务说明、制度与规范、SOP 与操作手册、标准与判据、案例与参考、模板与素材、系统与数据说明。来源形态、工作空间、主题标签、状态和访问范围是独立维度。SOP 是知识，Skill 是可调用的方法；数据字典是知识，持续变化的告警和订单属于业务数据。

工作资料是可长期重复引用的资料，不只是模板预设。临时文本、文件、图片和链接可以直接用于当前会话，默认不进入资料库；发送或转任务时固定本轮快照，需要复用时再由本人保存为带分类、范围和版本的工作资料。

用户可以直接在会话中要求 Agent 把当前内容或在线文档保存到指定空间和分类。条件明确时直接完成本人范围内可撤销的写入并返回版本回执；缺授权、目标歧义或扩大共享范围时才补问。后台资料页主要用于批量导入、目录治理和同步失败恢复。
