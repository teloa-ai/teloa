# 小智 MCP 助手通道插件

`@teloa/xiaozhi-mcp` 是可选 DSH/Cordis 插件。它让官方小智调用原小松鼠助手的三项操作：准备请求、提交原请求、查询原结果。设备保留官方固件，电脑主动连接官方 MCP 接入点，不开放工作台端口。

## 依赖与边界

宿主必须提供版本 1 的 `teloaAssistantChannels` 服务和现有 `credentials` 服务；没有兼容通道服务时不建立连接。DSH 固定版本为 `0.2.1-rc.2`。`cordis.patch.yml` 可供 DSH bundle 装载，但不属于 Teloa 默认组合。

插件只依赖公开类型契约，不读取宿主数据库、不选择会话、不调用任意工作台 RPC。兼容的社区宿主通过 `teloaAssistantChannels` 负责本人和安装归属、固定原助手、持久操作去重、最终输入准入、审批及正式结果。

这是同进程插件。它提供模块和生命周期解耦；Node 插件必须受信任，进程崩溃与代码权限不由这个边界隔离。

## 连接与停用

本人管理接口与 MCP 工具端口分开。保存接入点只将秘密交给凭据服务，不自动启用；更换接入点须重新授权。仅启用且已配置的通道建立连接。接入点对应官方智能体，不能用它识别物理说话人。

装载插件后，在工作台“设置 → 硬件连接”保存官方智能体的 MCP 接入点，核对准备、提交与结果返回权限，再单独授权启用。设置页只显示脱敏状态。加载插件、保存或关闭设置都不会自动启用；原助手还须有可用模型才能执行工作。

停用或卸载关闭新输入和结果外发，释放连接及管理处理器。宿主已受理的原工作继续运行，原会话、审批、成果和来源记录保留。长任务通过下一次查询返回，不承诺主动唤醒设备。

MCP 工具只包含 `teloa_request_prepare`、`teloa_request_submit`、`teloa_request_result`。它们不提供修改授权、批准审批、读取凭据、任意文件或历史的接口。

## 开发验证

```sh
pnpm --filter @teloa/xiaozhi-mcp test
pnpm --filter @teloa/xiaozhi-mcp build
```

测试使用本机协议端点和受控宿主端口，不会连接官方账号。协议和插件测试不能代替官方模型路由、TTS 或实体硬件验收。
