# 员工长期经验

当前源码支持用 Hindsight 0.10.3 提炼和检索员工的已确认记忆、已确认工作小结。默认关闭；配置服务后，员工在有明确业务范围的新任务和会话中使用经验。提炼异步进行，尚未完成或服务不可用时仍使用当前已确认正文。

本页适用于当前源码；已发布的 0.2.0-alpha.7 工件不因此获得新功能。Pro 的自包含运行包另行交付。

## 数据与来源

只发送当前本人、岗位版本和业务范围下仍然可用的确认来源。候选记忆、任意会话历史和分身私有记忆不会自动送出。查询会发送本轮输入的文本，最多 8000 字符；业务记忆依然由 Teloa 管理，Hindsight 是派生索引。

本人、安装身份、服务地址、岗位、范围或来源集合变化时使用新 bank，防止旧派生经验进入新请求。召回后再次检查来源。撤回会停止后续请求使用对应索引，并移除模型上下文中的旧经验快照；原始会话审计与旧 bank 保留。**撤回不是从外部服务物理删除数据**，删除和保留期限由部署者在 Hindsight 管理，不清理 Teloa 原始成果。

提炼回执写入业务数据库。丢回执重用相同操作身份；明确失败后间隔至少五分钟重试，单个来源快照最多三次。超过 512 条来源的索引预算、无法提炼或召回时继续使用最多 30 条当前确认正文，不阻断任务。经验正文按数据提供，不能授予新工具或权限。

配置 Hindsight 即授权该部署处理上述内容。即使 Hindsight 在本机，它使用的提炼 LLM 也会收到内容；本地向量模型和重排模型不需要把正文发送给另一家服务。已知宿主密钥会阻止外发，但不能据此保证任意人工粘贴的信息都可识别，部署者应选择适合其资料的模型服务。

## Docker 源码部署

先按根 README 配置源码构建。`compose.memory.yaml` 是可选叠加文件，使用独立 pgvector PostgreSQL、固定镜像摘要和稳定 worker ID。API 不映射主机端口，Teloa 经容器网络和独立令牌访问。

在仓库外创建私有目录，存放三个文件：`db-password`、`api-token`、`llm-key`。前两个使用独立随机值，最后一个是提炼模型的 API key。目录权限 `0700`；这三个文件设为 `0444`，以便容器非 root 用户读取，主机其他用户仍不能遍历私有目录。不要将目录或密钥加入源码。

```sh
export TELOA_MEMORY_SECRETS_DIR="/absolute/private/memory-secrets"
docker compose -f "compose.yaml" -f "compose.memory.yaml" config --quiet
docker compose -f "compose.yaml" -f "compose.memory.yaml" up -d --build
docker compose -f "compose.yaml" -f "compose.memory.yaml" ps
```

默认提炼服务是 DeepSeek `deepseek-v4-flash`。可以在执行上述命令的宿主环境里设置 `TELOA_MEMORY_LLM_PROVIDER`、`TELOA_MEMORY_LLM_MODEL`、`TELOA_MEMORY_LLM_BASE_URL`，三项应对应同一服务。初次启动会下载多语言向量和重排模型；后续从独立缓存卷复用。Full 镜像及模型占用数 GiB，启动速度取决于网络和机器资源。

关闭经验服务时先改用基础 Compose 重建 app，保留记忆卷。停机或备份时，记忆数据库、模型缓存和业务数据库是三个不同对象；备份业务数据库才能保留安装身份与操作回执。服务不可用不会阻止 app 启动。不要用 `down -v` 关闭功能，以免删除用户数据。

## 原生服务、CLI 与 npm

同一 HTTP 接口可连接官方 Python 或 npm 启动的服务。启动前显式选择模型、密钥、数据目录及监听地址，不让服务读取任意项目的 `.env`。

例如已有 uv 时，在隔离配置目录使用固定版本的官方 API；密钥只加入该服务进程环境：

```sh
uvx --from "hindsight-api==0.10.3" hindsight-api --host 127.0.0.1 --port 8888
```

官方 npm `@vectorize-io/hindsight-all@0.10.3` 是 Python 服务的启动与生命周期封装，需要 Node.js 22+ 和可用 `uvx`，不是纯 JavaScript 引擎。`hindsight-embed daemon start --profile <name>` 是 CLI 路线；两者的数据目录、停止和升级遵循各自官方说明。本批 Teloa 接入已有 API，不自动安装或启动这些守护进程。

启动 Teloa 前，在**继承的进程环境**中配置：

```sh
export TELOA_MEMORY_API_URL="http://127.0.0.1:8888"
export TELOA_MEMORY_API_TOKEN_FILE="/absolute/private/memory-api-token"
pnpm dev:dsh
```

外部服务使用 HTTPS。明确受信的容器私网 HTTP 才设置 `TELOA_MEMORY_ALLOW_HTTP=1`。超时默认 4000ms，可用 `TELOA_MEMORY_TIMEOUT_MS` 配置 100–60000ms。令牌文件必须是绝对路径；正式启动器剔除直接令牌环境变量，因此使用文件形式。项目 `.env` 无法开启服务、换外发地址或放宽 HTTP。

## 验证与限制

协议与来源测试分别使用本机 HTTP 和隔离 PostgreSQL；它们不代表真实模型质量。`scripts/验收经验记忆.mjs` 使用显式指定的私人模型凭据，仅发送脚本里的合成中文资料，启动并回收本轮独立容器。结果记录真实提炼、冷恢复、跨范围隔离和模型答复；没有调用真实服务时不会报告通过。

当前入口复用现有员工记忆确认和小结确认流程，不增加管理页面。只有明确配置服务的员工路径生效；分身、组织共享、自动全历史导入、Reflect 和 Mental Models 未接入。

官方参考：[安装](https://hindsight.vectorize.io/developer/installation)、[Node.js SDK](https://hindsight.vectorize.io/sdks/nodejs)、[npm 本地运行](https://hindsight.vectorize.io/sdks/hindsight-all-npm)、[CLI](https://hindsight.vectorize.io/sdks/cli)。HTTP 契约与镜像固定于 [v0.10.3](https://github.com/vectorize-io/hindsight/tree/v0.10.3)。
