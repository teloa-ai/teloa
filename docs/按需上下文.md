# 任务上下文按需加载

员工 API、工作台任务、自动化及群任务共用 Task/Run 组装；新运行标记 `contextMode: on-demand-v1`。本人运行沿用同样的资料目录投影。明确仅分析、纯文字回复及系统每日小结的执行保留原固定全文，不为加载目录增加执行工具。平台不识别 T1、设备品牌或安全域，员工按自己的职责和任务选择资料、方法。

## 启动输入与固定快照

- 资料目录：`resourceId`、`resourceVersion`、`title`、`purpose`、`sourceVersion`。目前资料模型没有单独的用途字段，目录从去掉 Markdown frontmatter 后的首个非标题行生成最多 160 字符的摘要，无正文时使用标题。
- Skill 目录：`name`、`description`（最多 600 字符）、`sha256`。内容摘要是实际固定版本的身份，不从名字推断版本。
- 员工职责、任务目标、工作模板的必要方法和授权要求继续常驻。员工包应将必须始终执行的精简主方法放在职责/工作模板中，把领域完整流程放入具有清晰适用描述的 Skills；平台不会自动摘要方法或猜测主 Skill。
- 完整资料与 Skills 仍存于服务端 `role_knowledge` / `role_skills`，用于审计、加载和防篡改。目录由这些快照确定性生成并逐次核对。现有数量与 256 KiB 合计快照保护继续保留；本次没有扩张绑定容量。
- “查看本次运行配置”展示实际发送的目录输入。宿主系统方法段也只放目录和加载约定，避免从另一路重新注入全文。
- 资料与 Skill 的有界目录随本次运行租约重新组装，压缩首次输入后仍可取得读取所需的固定身份；仅绑定资料、没有 Skill 的运行也保留这一能力。租约释放后不向后续会话留下目录，正文仍须按需读取。

## 按需工具

| 工具 | 参数与行为 |
| --- | --- |
| `teloa_knowledge_search` | 沿用既有岗位授权与 `query` / `limit` 契约。对新运行优先接纳版本、来源、区间和正文均匹配的语义结果，以固定正文关键词检索补充；模型未准备时使用关键词检索，不下载或加入索引。返回最多 8 个片段及实际覆盖范围，不能把未命中当作没有相关信息。 |
| `teloa_knowledge_read` | 按目录/命中的 `resourceId`、`resourceVersion`、`sourceVersion` 读取片段。`offset` 默认 0，`length` 默认 2000、最大 4000。位置是规范化换行后的 UTF-16 偏移，与检索 `chars` 一致；返回行号、总长度、`nextOffset` 和固定来源引用，可续读相邻章节。 |
| `teloa_skill_load` | 按目录中的 `name` 和 `sha256` 读取一份完整固定方法；不读取其他安装版本或未绑定技能，不扩大工具权限。 |

资料读取和 Skill 加载属于当前任务固定资源的只读能力，无需额外授予外部工具权限；普通会话、子 Agent 和其他 Run 不可冒用。宿主从可信会话解析 Run，不接受模型指定 `runId`、本人身份或业务范围。在同一数据库事务中复核运行状态、员工/委托范围和资料可读性；停止、撤权、撤回资源后拒绝交付正文。检索推理完成后再次复核资源范围。空绑定严格保持空范围。

资料按分析数据处理，Skill 只提供方法，二者均不能扩大权限。上下文压缩后需要时可重新加载。交付复核仅从本 Run 成功加载回执激活方法，资料依据来自实际读取/检索回执，不再把全部绑定正文作为已经提供的输入。PTC 代码模式中的加载须有当前 `run_code` 父调用区间内成对的原生子调用回执，并核对固定方法正文摘要；程序打印的正文不构成加载证据，外层程序失败也不抹掉已经成功完成的真实加载。程序未打印已加载正文时，复核租约仍提供这些固定方法全文，结束后移除；未加载的方法不进入该正文段。

## 兼容性

没有 `contextMode` 的历史运行仍按原全文格式读取和领取，原输入不改写。新旧模式均校验完整快照摘要、安装引用、任务和会话归属。资料改版只作用于未来运行；现有运行只能读取自己的固定内容，失效或缺失时明确报错。

按需快照使用数据版本 15。数据 1–14 经正常 `teloa upgrade` 入口先备份再迁移，初始化成功后才更新数据库版本标记；旧运行的固定输入保持不变。数据 15 不能直接交由数据 14 的旧发行读取或降级使用；需要回到旧发行时，按原版本恢复升级前备份到新目录。

## 原按需实现的验证

以下记录对应原按需上下文实现，不代替后续源码合并后的整体验证。

隔离 PostgreSQL 中创建 16 份资料、10 个 Skills 的真实 Task/Run：服务端完整快照保留，发送输入由 **177,616** 字符降至 **6,483** 字符，减少 **96.35%**。这是合成夹具的字符计数，不是用户原案例或真实模型 token/账单测量。

原生 DSH 执行链路捕获首个模型请求，检查用户输入和系统提示均无 Skill 正文；工具链验证选择加载、片段检索与续读、无模型回退、版本隔离、停止和撤权。后端测试同时覆盖旧全文运行恢复及新目录篡改拒绝，客户端测试覆盖目录回包和版本一致性。验收采用隔离数据库和脚本模型，不部署服务，也不读取用户实际员工或告警资料。
