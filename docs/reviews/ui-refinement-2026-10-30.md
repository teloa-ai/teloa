# 设计审查：Teloa 全站第二轮

## 概览

本轮针对 React Web 工作台做可见的层级与版式改进，定位是「交办工作、查看团队进展、阅读可追溯成果的工作空间」。保留暖灰底、墨黑主按钮、暖红点缀、现有标志和员工形象；识别特征由工作简报、清楚的目录与可阅读的成果承担。首页按用户要求保持上下排列。

本轮覆盖范围的评级：Good。验收区分真实页面巡查、隔离组件的密集数据测试与功能回归，不用自动化通过替代视觉观察。第一轮记录见 [apple-design-audit-2026-10-30.md](apple-design-audit-2026-10-30.md)。

## 设计尺度与布局

字号沿用系统字体栈：macOS 优先系统字体 / 苹方，Windows 使用 Segoe UI / 微软雅黑，不增加远程字体。14px 是用户字号的基准轴，产品各角色从它按比例生成：

| 用途 | 默认 CSS px | 字重 | 行高 |
| --- | ---: | ---: | --- |
| 说明、时间、标签 | 13 | 400–500 | 1.5–1.6 |
| 控件、快速检索、首页工作条目 | 14 | 400–500 | 1.5–1.6 |
| 正文、任务与员工目录 | 15 | 400–600 | 1.5–1.6 |
| 阅读正文 | 16 | 400 | 1.75–1.8 |
| 区块与卡片标题 | 18 | 600 | 1.5 |
| 弹窗标题 / 详情标题 | 22 / 24 | 600 | 1.4–1.5 |
| 页标题 / 主视觉标题 | 28 / 32 | 600 | 1.35–1.4 |

间距沿用 4/8/12/16/20/24/32/40px。主要目录版心上限 1360px，页面边距在 20–40px 之间适应窗口；卡片一般 20px 内边距，弹窗 28px、窄屏 20px。交互控件一般 38–40px，触摸与窄屏重要操作保留至少 44 CSS px。数据读数使用等宽数字，代码与终端保留独立字体设置。

颜色没有替换：浅色背景 #fbfaf7、内容 #1c1b19、表面 #ffffff、强调 #a34529；深色采用原有对应令牌。输入边界沿用第一轮独立语义令牌。现有对比度测试继续验证两套主题的正文/状态至少 4.5:1、输入边界至少 3:1。

常规窗口：

```text
导航      页位置 / 工作台页签
          首页标题与原生输入
          需要你处理的工作简报
          继续工作（名称 / 归属 / 状态 / 时间）
          自动化摘要
```

窄窗口：

```text
导航入口 / 页位置
工作台页签
首页标题与原生输入
工作简报与操作（可换行）
继续工作（状态、时间重排）
自动化摘要
```

任务与员工目录在桌面保持多列表格；窄屏按同一条目分组重排，保留原表头关系。宽屏不把长阅读段落无限拉宽。品牌不依靠增加装饰、渐变或玻璃材质表达。

## 已修正的关键问题

### Critical：首页命令菜单受到内部滚动器裁切

- **问题**：真实浏览器中，“/”菜单按窗口顶部定位，而首页上方还有页位置与页签；内部滚动器又把菜单的一部分裁掉。
- **依据**：`layout.md › Adaptability` 要求布局适应不同窗口；`accessibility.md` 的可达性原则适用于网页。此处菜单碰撞边界的处理属于实现判断。
- **修改**：首页由外层滚动；只在首页根据公开的 composer 标记、列表框和可见工作区计算菜单高度，空间不足时向下展开；放大导致输入离开可见区域时把打开菜单的输入区滚回可见范围。正文会话继续使用原生滚动器。
- **边界**：没有复制、搬移或替换 DSH 节点。观察器仅限本组件，关闭首页或卸载时解除；构建检查精确登记第六个已复核观察器，并增加不得搬移原生内容的检查。

### High：标题与目录层级被压平

- **问题**：任务、需要你、自动化的大标题原先隐藏；卡片与列表名称常与时间、说明使用近似字号，难以扫描。
- **依据**：`layout.md › Visual hierarchy`：“Group related items to clearly express related information or functions.” `typography.md › Supporting Dynamic Type`：“Maintain a consistent information hierarchy regardless of the current font size.”
- **修改**：恢复页标题；卡片名称、正文和元信息分别使用明确的字号与字重。选中任务时收起重复的目录页头，让标题空间交给当前对象。首页工作摘要、继续工作和自动化采用独立分组。

### High：固定卡高与小字号限制大字阅读

- **问题**：市场卡片原先固定为 200px；多个小组件仍有 9–13px 的固定字号或不随字号变化的像素行高。
- **依据**：`typography.md › Supporting Dynamic Type` 要求大字号下减少截断，并允许进入详情阅读完整内容。
- **修改**：市场卡片改为内容驱动的高度、同排对齐；标题/摘要可读两行，完整内容在原详情中保留。界面文本采用统一缩放轴，移除文字组件固定像素行高；头像字形、品牌字样、代码和终端仍保留各自尺度。

### High：密集目录全部挂载、窄窗需要横向追踪

- **问题**：大量任务、员工、市场项或资料会一次生成全部节点；窄窗表格难以把负责人、状态和所属对象联系起来。
- **依据**：`lists-and-tables.md › Content`：“Keep item text succinct so row content is comfortable to read.”
- **修改**：任务分组、员工、市场各卡片目录和资料表格分批挂载，每批 50 项；显示当前数量并提供继续展开。搜索仍作用于完整数据集，当前任务不因在首批之外而消失；筛选改变后重置展示窗口。任务/员工/资料在窄窗按条目重排，桌面保留表格。表头在自己的滚动区域内固定。
- **性能边界**：这是分批呈现，不是后端分页或全量虚拟滚动。项目沿用原有服务端游标；业务统计仍遵守已有协议的查询上限。员工当前工作从逐人过滤排序改为一次遍历建立索引。

## 品牌与平台边界

应用 Apple 的布局、排版、信息分组、反馈、可达性与渐进披露原则。44 的触摸尺寸使用 CSS px；字体缩放使用 rem 和用户字号轴。网页继续保留自身导航、显式明暗主题、原生 HTML 表单/表格、键盘焦点与浏览器行为。

不引入 macOS 菜单栏、iOS TabBar、原生 sheet detent、SF Symbols、pt 字号或系统专用 appearance 限制；没有把普通业务卡片改成 Liquid Glass。原有品牌色和角色形象继续承担识别作用。

减少的冗余是选中任务后的重复大页头，以及首页内部的第二个滚动区。原生会话、输入、草稿、模型执行和业务权限仍由原拥有者处理。

## 验收限制

实际数据库没有项目，项目密集目录以既有游标/组件测试及创建表单补验。预览复制数据库和资料正文，没有复制完整模型/会话执行环境，因此历史会话关联的运行可用性不作为本轮验收结论。浏览器巡查使用本机 Chrome；未声称完成 Safari、Firefox、真实触屏设备或人工读屏器验收。共享样式覆盖所有使用这些令牌的组件，未枚举每种业务插件、自定义看板布局和第三方应用中的全部数据组合。
