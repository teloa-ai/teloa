# UI 交互与详情连续性复核

分支：`codex/bugfix-ui-optimizations`。对照基线：`dec080e`。本轮针对六张问题截图补修，并复查同类控件、窄面板和长表单。

## 问题与改动

| 问题 | 调整后的行为 |
| --- | --- |
| 搜索输入同时出现内外两层焦点框 | 21 个组件的 22 个复合搜索由外壳显示焦点，独立输入框保留原来的键盘焦点提示；清除目录搜索后回到输入框。 |
| 下拉控件高度、字号和禁用反馈不一致 | 补齐选择控件的基础尺寸、主题和禁用样式，字体继承当前设置；保留原生键盘选择操作。 |
| 新建自动化占据列表上方，表单冗长 | 先在抽屉描述目标；手工设置复用标准表单弹窗，将业务与负责人、数据范围与交付要求配对。小屏或大字号自动改为单列，底部操作保持可达。 |
| 空的群目录仍提示“新建工作后，会话会保留在这里” | 会话、员工、群分别展示对应说明；群目录提供有权限时可用的创建入口。新入口沿用原导航确认，会话创建中禁用，取消切换不会触发新建。 |
| “用于其他业务”在资料页顶部插入大块内容 | 改为独立抽屉，错误在抽屉内显示；打开、关闭均不挤动原页面，关闭后回到触发入口。 |
| 宽窗口中的窄业务面板挤出逐字竖排 | 按业务面板自身的宽度响应，而非浏览器窗口宽度；统计改为四列、两列或单列，内容区和侧栏适时合并。 |
| 市场管理按钮与卡片脱离 | 业务范围、版本、升级提示和管理入口进入对应卡片；未匹配到目录项时仍保留可管理的独立条目。继续遵循个人版不显示后台空间名的约定。 |
| 点击任务后页头、搜索和目录突然跳动 | 桌面端保持页头、搜索边线和版心，限制目录宽度，精简重复元信息；详情使用独立面板。返回保留查询和滚动位置，大字号窄详情采用上下排列的属性。 |

复查时还补齐了自动化目录每批 50 条展示与全量搜索；修正无必要的同页导航，避免在浏览器存储不足时重新打开创建流程丢失本窗口草稿。

完整回归中同步修正了旧测试夹具：群消息夹具接入已有的真实分段加载模块；自动化测试改为从实际创建入口打开抽屉，字体检查读取当前计划行；草案目录明确区分恢复与继续入口；API 身份替换夹具先提交替换再释放旧回包，原有拒绝旧结果的断言保持。

## Web 与原生平台边界

此次采用的是适用于网页的信息层级、排版、流式布局、按实际容器回流、显式提交、键盘焦点、关闭回焦和减少动态效果原则。尺寸以 CSS 像素和用户字号验证；任务面板的轻量入场效果尊重 `prefers-reduced-motion`。

Apple 原生平台的 pt 尺寸、系统导航结构、系统材质及平台专属组件规范不作为网页的硬性布局规则。现有暖灰、墨黑品牌和 Web 控件保持一致。

资料采用继续使用固定版本、独立副本和原有幂等恢复协议；自动化保留原会话与草稿，手工新计划仍以暂停状态保存。本轮没有更改后端契约、权限或执行规则。
